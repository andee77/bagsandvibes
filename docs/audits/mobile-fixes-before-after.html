Mobile fixes: before / after at 375 px

Proposal for your approval. Nothing is deployed. "Before" is the live site today.

How the "after" screenshots were made. The new CSS was injected into the live pages in the browser pane, directly after the real stylesheet so the cascade order matches production. The two PHP changes (logged-out menu, label on the reset field) are previewed with the exact markup the server tests produced. Nothing was written to the site. Desktop width was not re-checked visually (the pane gets a robot check at desktop size), but the new CSS is limited to widths of 860 px and below, apart from two rules noted under items 2 and 6. After deploy I will re-verify everything live at 375 px and re-check desktop in a place the CAPTCHA allows.

1. Homepage "One-Stop Shop" section no longer clipped

Cause: the section holds two copy cards and the phone layout put them side by side in a row (one 57 px off each edge). Fix: stack them and let the no-wrap headline wrap. After: both cards at x=20–355 on a 375 px screen.

2. Page-title ribbon fits and wraps

Cause: ribbon and title forced onto one line (387 px wide, page widened to 406 px). Fix: ribbon never wider than its container, title wraps. After: ribbon 338 px wide, page exactly 375 px, MENU button fully visible. This rule also applies on desktop but changes nothing there unless a title is wider than the page.

The label comes from Ultimate Member's own per-field filter, so it uses UM's normal label markup (tested on the server: the reset form renders <label for="username_b">Username or E-mail</label>). The Register page was measured earlier and is covered by the same CSS rule; I did not take a separate screenshot of it.

5. Logged-out visitors no longer see Dashboard / Logout

A logged-out visitor on a Gate, Login or Register page gets a three-item menu: Home, Sign in, Register. Same markup and classes, so the same CSS and script drive it. Logged-in members get exactly the same menu as before (verified byte-for-byte against the live function for a member and for the admin). Before: the screenshot under item 3.

6. Open dropdown label no longer disappears

Cause: Kadence paints a focused or tapped button gold, and our label is gold too. Fix: dropdown and MENU buttons stay transparent in every state. After: the label is gold text on the dark menu; the open MENU button gets a gold outline. The same bug exists on desktop for a focused dropdown button, so this rule applies there too (making it transparent, as the stylesheet always intended).

What I could not verify before deploy

  • A real logged-in member session (the pane's session expired). The member menu is verified identical by code comparison; please confirm in your own login after deploy.
